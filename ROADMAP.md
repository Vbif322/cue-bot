# Roadmap

Следующие этапы по убыванию приоритета. Ближайшие задачи — в [TODO.md](TODO.md); когда они
заканчиваются, верхний этап отсюда разбивается на задачи и переезжает в TODO.md.

## 1. M8 — Федерации и подписки

- [x] Федерации как сущность над турнирами: `federations` + `federation_members`, роли
      owner / organizer (судьи остались per-tournament в `tournament_referees`),
      `tournaments.federationId` (NULL = платформенный турнир). Модель прав — `authz.ts`.
- [x] Глобальный `role='admin'` → платформенный супер-админ; `requireStaff` для организаторов,
      панель скоуплена по федерации (переключатель), ростер игроков без контактов.
- [x] Бот: `/new_federation`, `/my_federations`, шаг «организатор» в мастере, вкладка
      «Организую», город игрока и фильтр ленты по городу; видимость `unlisted`.
- [x] Сайт игрока: фильтры ленты по городу и организатору, `GET /api/app/federations`.
      Групповые чаты привязываются к федерации.
- [x] Право организатора — платная опция: `users.organizerUntil` выдаёт админ; без него нельзя
      создать организацию, по истечении у владельцев организация не создаёт новые турниры.
- [ ] Подписки на организаторов (`federation_follows`): фильтр «Мои организаторы»,
      уведомление подписчикам об открытии регистрации.
- [ ] Оплата права организатора поверх платёжной инфраструктуры M3 (после этапа 5): сейчас
      срок продлевает админ вручную; напоминание об истечении срока владельцу.

## 2. Поматчевое расписание (`per_match`) — доведение

Под сценарий «турнир идёт месяцами, матчи назначаются по мере доступности игроков».

- [ ] **Самозапись/согласование времени игроками.** Handshake «игрок предложил время →
      соперник принял/отклонил» по образцу `reportResult`/`confirmResult`
      (`src/services/matchService.ts`); сейчас время ставит только организатор/судья
      (`canManageTournament`). Поверх confirm-флоу M2-7.

## 3. Генерация регламента турнира

- [ ] Автоматическая сборка регламента из настроек турнира (дисциплина, формат сетки,
      до скольких побед/фреймов, расписание, оргвзнос, правила техпоражений и споров).
- [ ] Шаблоны регламента (в т.ч. на уровне федерации) с правкой организатором перед
      публикацией; выгрузка в PDF и ссылка в боте / на странице турнира.

## 4. Лендинг

- [ ] Публичная страница продукта: что умеет бот, сценарии для организаторов и федераций,
      ссылка на бота и вход в веб.
- [ ] Витрина открытых турниров с регистрацией; SEO / превью для шаринга.

## 5. M3 — Платёжная система с автоматическим распределением средств

- [ ] Приём оргвзносов / входных платежей за участие в турнире (оргвзнос задаёт организатор).
- [ ] Призовой фонд и автоматические выплаты победителям по итогам сетки.
- [ ] Автоматический сплит: платформа / организатор / федерация / призовой фонд по
      настраиваемым правилам.
- [ ] Платёжный провайдер со сплитами и выплатами (ЮKassa / CloudPayments / Stripe Connect —
      выбрать под рынок): вебхуки, идемпотентность, история транзакций, возвраты / споры.
- [ ] Финансовый учёт: `payments` / `transactions` / `payouts` + ledger; платёжные/выплатные
      реквизиты пользователя.

## 6. M4 — Рейтинговая система

Сейчас статистика «сыграно/победы/поражения» считается на лету в `userStatsService.ts`, а
лидерборд — только по макс. брейкам (`leaderboardService.ts`).

- [ ] Рейтинг по каждой дисциплине (ELO или Glicko-2) в таблице `player_ratings`
      (`userId` × дисциплина → значение + история).
- [ ] Пересчёт при подтверждении результата (`matchService.ts`) с учётом техпобед / walkover и
      каскада коррекций.
- [ ] Таблицы лидеров по рейтингу (сервис + API + команда бота); рейтинги в профиле игрока.

## 7. M5 — Организаторы в вебе + привязка Telegram

- [ ] Создание и управление своими турнирами из браузера, ресурсно-ограниченные права.
- [ ] Привязка Telegram-аккаунта к веб-аккаунту (переиспользовать код-/токен-мост).

## 8. M6 — PWA

- [ ] Игровой веб (`app/`) устанавливается как приложение: web app manifest, иконки,
      service worker (офлайн-оболочка), подсказка установки.
- [ ] Push-уведомления как ещё один канал доставки поверх `sendNotification`.

## По спросу

- [ ] **Лист ожидания.** При достижении `maxParticipants` (`registerParticipant` в
      `src/services/tournamentService.ts`) ставить в очередь, при освобождении места —
      авто-продвижение и уведомление (тип `participant_limit_reached`).
- [ ] **Дисквалификация (DQ).** Команда судьи/организатора → запись в `disqualifications`,
      статус участника `disqualified`, техпоражение текущего матча через
      `setTechnicalResult`, уведомление `notifyDisqualification`.
